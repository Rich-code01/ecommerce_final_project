# AUCA Big Data Analytics — E-commerce Project

## Project Structure

```
project/
├── dataset_generator.py        # Step 0 — generate all JSON data
├── part1_mongodb.py            # Part 1a — MongoDB schema + aggregations
├── part1_hbase.py              # Part 1b — HBase schema + queries
├── part2_spark_processing.py   # Part 2  — Spark batch + SQL analytics
├── part3_integration.py        # Part 3  — Cross-system integrated queries
├── part4_visualizations.py     # Part 4  — Charts for report
│
├── ecommerce_data/             # Generated by dataset_generator.py
│   ├── users.json
│   ├── categories.json
│   ├── products.json
│   ├── sessions_0.json
│   ├── sessions_1.json ...
│   └── transactions.json
│
├── spark_outputs/              # Generated by part2
├── integration_outputs/        # Generated by part3
└── visualizations/             # Generated by part4
```

## Setup

```bash
# 1. Install Python dependencies
pip install faker pandas pyspark pymongo happybase matplotlib seaborn

# 2. Start MongoDB (if not running)
mongod --dbpath /data/db

# 3. Start HBase via Docker
docker run -d -p 2181:2181 -p 9090:9090 dajobe/hbase
```

## Run Order

```bash
# Step 0 — Generate dataset (run this FIRST)
python dataset_generator.py

# Part 1a — MongoDB
python part1_mongodb.py

# Part 1b — HBase (needs Docker running)
python part1_hbase.py

# Part 2 — Spark (generates spark_outputs/)
python part2_spark_processing.py

# Part 3 — Integration (generates integration_outputs/)
python part3_integration.py

# Part 4 — Visualizations (generates visualizations/)
python part4_visualizations.py
```

## Technology Selection Justification

| Data | Technology | Reason |
|------|-----------|--------|
| User profiles, Products, Transactions | **MongoDB** | Rich nested documents, aggregation pipelines, flexible schema |
| Session time-series, Product daily metrics | **HBase** | High write volume, time-range scans, sparse columns, row key locality |
| Cross-dataset analytics, batch computation | **Apache Spark** | Distributed processing, in-memory joins, SQL interface, handles multiple JSON files |
